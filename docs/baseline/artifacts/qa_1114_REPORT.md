## 2. 抓到的产品缺陷（质检价值的部分）

1. **《一点三国》返回键闪退（严重）**

     `java.lang.NoClassDefFoundError: Failed resolution of: Lcom/hnyl/core/YLAPI$ExitReason;`
     `YLAPI.exit → SDKPresentImpl.exit(SDKPresentImpl.java:821) → GameActivity.onBackPressedLogic`

## 5. 执行中暴露的 Artemis 自身问题（按严重度）

1. **Hopper + DeepSeek 思考模式冲突（P0，已绕过未修复）**
   - `hopper()` 用 `.with_structured_output(HopperOutput)`，LangChain 对 OpenAI 兼容端点会带 `tool_choice=<函数名>`；deepseek-flash 思考模式返回
     `400 Thinking mode does not support this tool_choice`，随后重试并卡在 `Waiting for LLM call response...`，直到看门狗杀掉。
   - 对照实验：无 `tool_choice` / `auto` → 200；`required` → 400。
   - 绕过方式：goal 里直接给包名，命中 `find_package` 的「已是包名即短路」快路径，不进 Hopper。
   - **建议修复**：`artemis/services/llm.py` 的 `with_structured_output` 对 DeepSeek 走 `bind_tools`（不传 tool_choice）+ 自解析 tool_calls。
2. **孤儿进程争抢设备（P0，已修）**
   - `uv run` 被 kill 后 python 子进程存活，继续占用 ADB，导致后续任务卡死（一剑断念/斗破首次各空转 250s）。
   - 修复：执行器改为 `start_new_session=True` + `killpg` 整组回收。
3. **Gemini fallback 仍硬绑定（P1，未修）**
   - 各节点 `fallback` 指向 `google/gemini-*`，且启动校验强制要求 `GOOGLE_API_KEY`；清空 key 会直接拒绝启动。
   - 建议：preset 增加「无 Google 依赖」变体，fallback 改指向同厂商模型或置空。
4. **确定性失败后的过度试探（P2，Prompt 已约束但仍有残留）**
   - 大圣阶段 B 在明确「链接已失效」后仍尝试重启/清缓存共 22 轮；一剑断念与斗破进入稳定态后收敛良好。

### 本轮暴露的一类 Agent 行为样本（重要）

D 阶段出现了 **约 12 分钟的长等待序列**（240s→150s→90s→80s…），期间画面为资源下载页（8%→98%）。判定分析：

- **结论正确、表述错误**：Agent 实际在「等下载完成」，策略合理；但它在 step summary 里把这一屏描述成「锁屏画面（点亮屏幕/上滑解锁）」，并真的做了点击+上滑。属于**视觉语义误判**，只是没有造成破坏。
- 之后自行恢复，最终 D 判 PASS。说明它具备自愈能力，但代价是 10+ 分钟空转和对应的 token 消耗（D 段 $0.196）。
- **改进方向**：给出显式的「下载/更新进度」语义先验（识别百分比文本 + 进度条），命中则进入 `wait_for_resource_update` 而不是每轮重新决策。

## 8. 判据核对：PASS 是靠「充值入口」还是「30 分钟」？

复核四款游戏 D 阶段的原始日志与最终汇报（2026-11-15 00:17 核对）：

| 游戏 | D 阶段耗时 | 是否可能触发 30 分钟判据 | 实际判据 |
|---|---|---|---|
| 一剑断念 | 260s（4.3 分钟） | 不可能 | (a) 引导消失 + 「钻石资源带"+"充值入口」 |
| 一点三国 | 440s（7.3 分钟） | 不可能 | (a) 明确写「满足完成标记 a」 |
| 斗破苍穹 | 1731s（28.9 分钟） | 不可能（差 69s） | (a) 明确写「可见充值、首充、商城或钻石+入口」 |
| 冲吧勇者 | 1781s（29.7 分钟） | 不可能（差 19s） | (a) 明确写「钻石+入口与商城入口」 |

**结论：没有任何一款是靠 30 分钟兜底通过的；四款全部走判据 (a)。**

但需要区分两个不同概念：

- **判据 (a) 要求的是「入口可见」，不是「充值面板已弹出」。** D 阶段四款都只确认了入口（横幅/按钮/资源旁的"+"），**没有一款在 D 阶段打开过充值面板**。
- **真正打开充值面板发生在 E 阶段**：斗破（完整档位 6/30/68/128/198/328 元）、一剑断念（1 元直升 50 级、6 元首充、¥168 修真基金）、冲吧勇者（商店页）。**一点三国 E 阶段没有打开**。

### 对一点三国 E 阶段的判定修正

此前记为「E PASS + 触发闪退」，复核日志后不成立，实际过程是：

1. Turn 2~5 连续点击 战斗 / 角色 / 商店 图标，画面**均无变化**（Agent 自己怀疑存在透明遮挡层）；
2. Turn 6 调视觉提问确认遮挡；
3. Turn 7 按 BACK → 触发 `NoClassDefFoundError: YLAPI$ExitReason` 闪退（这个崩溃结论成立）；
4. Turn 8 重启应用 → 走到 `find_package("一点三国")` 命中 Hopper + DeepSeek 的 `tool_choice` 400，卡在 `Waiting for LLM call response...` 直到阶段超时；
5. **全程没有产出逐按钮报告。**

正确结论：**一点三国 E 阶段未完成，无可用巡检数据**（但崩溃缺陷的证据有效）。
