# Fabric 内 Loop

先读任务的目标、范围、验收和反馈。按当前 Orca Dispatch 的注入前言工作，不从旧文件复制生命周期权限。

- 先检查实际代码与任务；将一个完整行为改动做完再交付，不把零散待办返回给协调者。
- 实现 → 执行验收 → 诊断失败 → 最小修复。新增功能配必要测试；不为低风险文档改动制造测试仪式。
- 返工先读上一轮 REVIEW.md 和候选位置，逐项回应；不能清空问题或换验收条件取得 PASS。
- 使用当前 Agent 的原生工具与审批。权限或需求阻塞按 Orca ask/escalation 交协调者，不换危险参数或自动批准。
- 在任务指定的轮目录写 DELIVERY.md：目标、实际修改、候选工作区、运行过的命令与结果、未完成项。没运行就写未运行。
- 多候选模式另保存候选与冻结验收文件的摘要、每条源码/构建/最终制品检查的实际对象、命令、退出码、日志和环境。最后一次构建后重新验证**该**最终制品；没有运行的项目检查保留未知，不移用旧制品 PASS。
- 完成交付后先检查收件箱，再按本次注入前言发送 worker_done，明确 succeeded 或 failed，并提供真实 report-path。结束当前工作并停止编辑，等待新的 Dispatch。

未提供有效 Orca 生命周期前言时，只输出交付并报告缺少调度上下文，不伪造 Task/Dispatch ID。不修改 Fabric 配置、角色规则或任务约束。commit/push/merge/deploy 需要用户针对目标仓库的授权。
