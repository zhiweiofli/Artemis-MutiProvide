# 任务上下文准备（Task Context）

本参考将项目背景与长期记忆转化为当前任务可直接消费的行动上下文，供运行时 Agent 或团队角色在执行前准备任务材料。

## 1. 区分 Memory 与 Task Context

- **Memory（长期背景）**：用户长期关注、历史决策、项目演进沿革、协作偏好。Memory 不能原样塞入执行上下文。
- **Task Context（当前任务上下文）**：直接影响本次行动的目标、非目标、作用范围、硬/软约束、关键代码事实与验收标准。

### 修正自动升级链

严禁沿 `Identity → Preference → Rule → Action` 自动把背景推断为硬规则：
1. **身份不证明偏好**：用户或项目的技术背景不能自动推导本次任务必须采用某种重型流程。
2. **偏好不必成为硬规则**：历史偏好可作为默认候选（`default / heuristic`），不能静默覆盖当前任务目标或项目已接受契约（`invariant`）。
3. **历史行为不等于当前授权**：此前会话批准过的提交、发布、安装或模型调用，不自动延续为本轮授权。
4. **记忆可能只是一条时点事实**：引用历史结论前先对照当前仓库文件与版本。

## 2. 信息分类与来源标记

准备任务上下文时，将关键信息明确区分为四类：

| 类别 | 含义与处理要求 |
|---|---|
| **仓库事实（Fact）** | 当前工作区已核实的代码、配置、构建输出或 SHA-256 摘要；给出文件路径（必要时含行号或版本） |
| **用户明确要求（Requirement）** | 用户在本轮或已确认决定中明确指定的目标、边界与取舍 |
| **历史观察（Observation）** | 既有报告、旧会话交接或复盘记录；仅对**可能变化且影响本次决策**的状态标注读取时间/版本 |
| **待验证假设（Hypothesis）** | 尚未被代码或运行结果证实的推断；必须写明验证方式及假设不成立时的回退影响 |

不为每句普通描述堆砌元数据；只标记影响行动与验收的关键判断。

## 3. 简繁任务分流与最小语义结构

- **普通小任务（对话内完成）**：单文件/小范围明确修改、只读诊断或快速验证，直接在对话中对齐目标、范围与验证命令，**不强制新建任务文档**。
- **复杂、跨会话或团队协作任务（落盘复用）**：需要多角色配合、新会话接手或使用 Fabric 执行控制时，复用项目现有任务文件或交接文档，最少表达以下 6 项语义内容：

```markdown
目标与交付：本次要改变的行为、具体交付物、下游使用者。
范围与约束：允许写入的路径、必须保护的接口/基线、明确排除项。
相关事实：足以支持行动的仓库事实摘要 + 文件路径/版本来源。
未知项：待验证假设；若失败会影响什么，怎样通过实验或检查消除。
执行入口：选用角色与能力条件入口（或直接执行）；真实构建/测试/检查命令及来源。
完成标准：可观察结果、分层验收方式、交接所需证据路径。
```

这是一组语义要求，不是新的 JSON schema，也不要求导出模型内部思维链。执行中发现新证据时，原地更新相关事实与未知项，不重复拷贝整份项目契约。

## 4. 与可选 Fabric 的衔接

当项目任务选用 Fabric 作为单次执行控制底座时：

- 继续使用 Fabric 既有的计划任务项结构（`key / title / role / file / deps`），将上节 6 项语义内容写入 `file` 指向的任务 Markdown 正文。
- Fabric 负责冻结该任务正文与单次 Run 的派工/审查/裁决证据，**不解释业务 Skill 语义**，也不会自动冻结正文外链的全部文件。
- 因此，**影响复现与验收判定的关键事实（如目标接口签名、基线摘要、禁止修改路径、精确验证命令）必须直接写入任务正文**；其余参考材料按 [交接约定](handoff.md) 记录路径与 SHA-256 摘要。
